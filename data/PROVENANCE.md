# Example data: provenance, units and schema

Both files were generated by `src/tools/make_sample_data.cpp` for this project. No third-party geometry or results were used. Both are released as CC0 (public domain).

Regenerate with: `wb_make_sample_data data`

## heatsink_fins_mm.stl

| | |
|---|---|
| Provenance | Self-created. A 60 × 40 × 5 mm base plate with six 2 mm × 25 mm fins, built from axis-aligned boxes |
| Format | ASCII STL, single `solid heatsink_fins_mm`, 84 triangles, 10.3 KB |
| Units | **millimetres** (STL itself stores no units; select "millimetres" in the Geometry view, which is the default) |
| Notes | Built from overlapping boxes, so it is a visual model, not a watertight manifold. Outward normals are written explicitly and match the counter-clockwise winding |

## heatsink_nodal_SYNTHETIC.csv

| | |
|---|---|
| Provenance | **SYNTHETIC — not an ANSYS export.** Temperatures come from a closed-form field: a Gaussian hot spot under the base centre (25 °C ambient + 55 °C peak rise, σ = 18 mm), a 1.5 °C drop through the base thickness, and the classic straight-fin profile cosh(m(H − s))/cosh(mH) with m = 0.06 /mm, H = 25 mm up each fin. It looks plausible, but it is not a solved result |
| Format | CSV, 2 295 nodes, 66 KB. Four `#` comment lines at the top say it is synthetic |
| Schema | `node_id,x_m,y_m,z_m,temperature_C`: the column layout the brief specifies for an ANSYS nodal temperature export |
| Units | coordinates in **metres**, temperature in **°C** (rounded to 0.001 °C) |
| Nodes | Base: 2.5 mm grid in x, y and through the 5 mm thickness. Fins: the mid-plane of each fin on a 2.5 mm grid |

## Producing a real file in ANSYS (for reference)

In ANSYS Mechanical a nodal temperature result is typically exported with *right-click the result → Export → Export Text File*. That gives node number, X/Y/Z location and temperature, usually with units in the column titles (e.g. `X Location (mm)`). To use it here:

1. Make sure coordinates are in metres and temperature in °C (set *Units → Metric (m, kg, N, s, V, A)* before exporting, or convert).
2. Rename the header to exactly `node_id,x_m,y_m,z_m,temperature_C`, comma-separated with no quotes.
3. Save as `.csv` (UTF-8, with or without BOM).

The reader rejects anything that does not match, with a message naming the line and the problem.

## Tested file-size limits

From `results/io_size_limits.csv` (Apple M2, Release build):

| File | Records | Size | Parse time | Result |
|---|---|---|---|---|
| ASCII STL | 100 000 triangles | 10.4 MB | 47 ms | ok |
| ASCII STL | 500 000 triangles | 53.4 MB | 235 ms | ok |
| ASCII STL | 800 000 triangles | 85.6 MB | — | rejected: above the 64 MB limit |
| Nodal CSV | 1 000 000 rows | 28.1 MB | 185 ms | ok |
| Nodal CSV | 1 000 001 rows | 28.1 MB | — | rejected: above the 1 M row limit |

These are parser limits and timings. Browser rendering of the largest files was not benchmarked; the bundled examples (84 triangles, 2 295 nodes) render instantly, and very large files will mainly be limited by the JSON transfer and the GPU of the viewing machine.
